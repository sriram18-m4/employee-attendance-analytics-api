# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | Database connection / `/health` | `/health` returned static 200 without checking if MongoDB was actually reachable. | Stop MongoDB service; `/health` still responded 200 instead of 503. | Added `client.admin.command('ping')` inside `/health` wrapped in a try/except returning HTTP 503 on failure. |
| 2 | Startup / Indexes | No indexes were created at startup, leaving uniqueness unenforced by the engine. | Concurrent creates with identical `emp_code` both succeeded with 201; queries performed `COLLSCAN`. | Created idempotent indexes at startup: unique on `employees.emp_code`, unique compound on `attendance_logs.(emp_code, date)`. |
| 3 | `create_employee` | Performed check-then-insert (`find_one` then `insert_one`), creating a race condition on concurrent requests. Lacked regex validation for `emp_code`, email, and shift times. | Two concurrent requests with `EMP0001` both passed the check; invalid codes like `ABC123` were accepted. | Used Pydantic validation for patterns and shift check (`shift_start != shift_end`), and caught `DuplicateKeyError` to return HTTP 409. |
| 4 | `list_employees` | Offset calculation used `skip = page * page_size`, which skips page 1 completely. `total` ignored the `department` filter. Missing sort on `emp_code`. | Requesting `page=1` returned items starting at index 20; `total` showed entire collection count instead of filtered count. | Fixed pagination offset to `(page - 1) * page_size`, applied `filter_query` to `count_documents`, and sorted by `emp_code: 1`. |
| 5 | Timezone & instant parsing | Instants were parsed using naive `datetime.now()` / `datetime.fromtimestamp()`. Epoch seconds vs milliseconds were not checked. | Timestamps lost UTC alignment in IST calculations; timestamps < 100000000000 (seconds) were accepted instead of returning 422. | Built strict epoch-millisecond validator (`StrictInt`, rejecting floats/strings/<100B/>4.1T) and converted to UTC timezone-aware datetimes. |
| 6 | Attendance date & R1 (Overnight shifts) | Assumed calendar date of punch is always attendance date; failed for overnight shifts (e.g., 22:00-06:00). Did not truncate instants to whole seconds. | Punching in at 05:30 IST for a 22:00-06:00 shift got assigned to today instead of previous day's shift date. | Implemented R1 helper: converts to IST, truncates milliseconds to whole seconds, and subtracts one day if `shift_end <= shift_start` and punch time < `shift_end`. |
| 7 | `compute_late_minutes` (R2) | Used `int(minutes)` and checked `minutes > 10`. Ignored IST timezone and overnight shift boundaries. | Punch-in at 09:40:01 for a 09:30 shift truncated to 10 min, failing `> 10` check and reporting 0 late minutes instead of 10. | Computed exact elapsed seconds from `shift_start`; if `seconds > 600`, returned `floor(seconds / 60)`, else 0. |
| 8 | `compute_work_hours` (R4) | Used standard float division and Python's `round()`, which applies banker's rounding (round-half-to-even). | A duration resulting in x.xx5 rounded down to even instead of half-up; floating point precision artifacts appeared. | Calculated `(punch_out - punch_in).total_seconds() / 3600` using `Decimal` with `ROUND_HALF_UP` to 2 decimal places. |
| 9 | `compute_overtime` (R3) | Ignored overnight shifts, ignored the 30-minute minimum threshold, and mixed naive and aware datetimes. | Punch-out 10 minutes after shift end returned 10 overtime minutes instead of 0. | Calculated minutes between shift end and punch out; returned `floor(minutes)` only if $\ge 30$, otherwise 0. |
| 10 | `compute_half_day` (R5) | Missing or evaluated against unrounded work hours. | A shift with 4.496 hours (rounded to 4.50) was misclassified as half-day. | Evaluated condition strictly against the rounded `work_hours < 4.50`. |
| 11 | `punch_in` | Crashed with 500 on unknown employee. Check-then-insert race condition. Status was not restricted to presence statuses. Leaked `_id` and raw datetimes. | Punching in for non-existent employee threw 500; status `ABSENT` was accepted at punch-in; response failed serialization. | Added 404 check for employee; validated status is in `[PRESENT, WFH, ON_DUTY]`; caught `DuplicateKeyError` to return 409; sanitized response. |
| 12 | `punch_out` | Used non-atomic check and update; did not search for the most recent open record across midnight; failed validation when `punched_at <= punch_in` or `> 24h`. | Concurrent punch-outs both succeeded; overnight punch-out failed to find previous day's punch; punch-out before punch-in returned 200. | Queried most recent record with `punch_in <= punched_at`, validated `punch_in < punched_at <= punch_in + 24h`, and used atomic `update_one` with `punch_out: null` filter returning 409 if already closed. |
| 13 | `list_attendance` | Loaded the entire collection into Python memory (`list(db.attendance_logs.find())`) and sorted in memory. Ignored secondary sort. | High memory spike and timeout on 100k docs; records with same date had non-deterministic order; `date_from > date_to` did not return 422. | Pushed filtering, sorting (`date: -1`, `emp_code: 1`), `skip`, and `limit` to MongoDB engine; added 422 validation for date range. |

## Looked at and decided NOT a defect

1. **`load_dotenv()` without `override=True`:**
   - In Python's `dotenv`, `load_dotenv()` defaults to not overwriting variables already present in `os.environ`.
   - Because real environment variables passed by the host system/container automatically take precedence over `.env`, this matches the requirement: *"Read MONGO_URI and MONGO_DB from real env vars (they win over .env)."* Therefore, keeping standard `load_dotenv()` behavior is correct.
